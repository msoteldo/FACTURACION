# Webapp de escritorio (un usuario): plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usa superpowers:subagent-driven-development (recomendado) o superpowers:executing-plans para implementar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`) para el seguimiento.

**Objetivo:** facturar tickets desde el navegador de la computadora y editar los datos fiscales guardados en Postgres, sin romper la API ni el bot de Telegram.

**Arquitectura:** una SPA en JS puro (módulos ES, sin build) que FastAPI sirve en `/`. El login usa la `API_KEY` como contraseña y responde con una cookie HMAC. Los datos fiscales salen de una tabla de una sola fila (`perfil_fiscal`) a través de `obtener_datos()`, que `GestorTrabajos` llama al crear cada trabajo.

**Stack:** FastAPI, SQLAlchemy 2.x, Alembic, psycopg 3, Playwright (E2E), pytest.

**Spec:** `docs/superpowers/specs/2026-10-27-webapp-design.md`. Léela antes de cada tarea; este plan no repite los textos de la interfaz ni las tablas de errores que la spec ya fija.

## Restricciones globales

- Versiones exactas (`==`) en `requirements.txt`: `sqlalchemy` ≥ 2.0, `alembic` ≥ 1.13, `psycopg[binary]` ≥ 3.2, usando la última estable al implementar. No se agregan otras dependencias de Python ni ninguna de JS.
- Nombres, mensajes y comentarios en español, como el resto del repo.
- La CSP es `default-src 'self'; img-src 'self' blob:; frame-ancestors 'none'`. Eso implica: nada de `<script>` ni `<style>` inline, nada de atributos `style=` ni `on*=`. El JS usa clases CSS y `addEventListener`.
- El JS pinta todo texto del servidor con `textContent`. `innerHTML` está prohibido salvo con literales fijos.
- El seguimiento (`GET /facturas/{id}`) y la verificación de la cookie **no** tocan la base.
- `pytest` debe pasar completo al final de cada tarea.
- Sigue `--workers 1`.

## Revisión: casos que más pueden fallar

1. **Pegar la contraseña con espacios o comillas** (como ya pasa con el header) → el login la acepta. Prueba en la Tarea 4.
2. **Cookie válida pero el servidor sin `API_KEY`** → 503, igual que hoy con el header; nunca se abre el acceso. Prueba en la Tarea 4.
3. **RFC en minúsculas o con espacios en `PUT /perfil`** → se guarda sin espacios y en mayúsculas. Un CP con 4 dígitos da 422. Prueba en la Tarea 3.
4. **Abrir directo `#/trabajo/<id>` de un trabajo que no existe** → mensaje de "el servicio se reinició…" y **no** sigue consultando. Prueba en la Tarea 6.
5. **Trabajo terminado** → la web deja de consultar `GET /facturas/{id}`; si siguiera, Render nunca se dormiría. Prueba en la Tarea 6.

### Tarea 4: Sesión con cookie

**Archivos:**
- Crear: `app/sesion.py`
- Modificar: `app/main.py` (`requiere_api_key` pasa a aceptar header o cookie; `app.include_router(sesion.router)` sin dependencias)
- Prueba: `tests/test_sesion.py`

**Interfaces:**
- Produce en `app/sesion.py`:
  - `DURACION_S = 12 * 3600`, `COOKIE = "sesion"`
  - `clave_firma(api_key: str) -> bytes`: `hmac.new(api_key.encode(), b"sesion-web", sha256).digest()`
  - `crear_token(api_key: str, ahora: float) -> str`: `f"{exp}.{hmac_hex}"`, con `exp = int(ahora) + DURACION_S`.
  - `token_valido(token: str, api_key: str, ahora: float) -> bool`: `False` ante cualquier formato roto; usa `compare_digest`.
  - `limpiar_clave(valor: str | None) -> str`: strip de espacios y comillas, igual que el código actual.
  - `class LimiteIntentos(maximo: int = 5, ventana_s: float = 60)`, con `bloqueado(ip, ahora) -> bool`, `fallo(ip, ahora) -> None` y `reiniciar() -> None`. Instancia de módulo: `limite`.
  - `router`:
    - `POST /sesion` con `{"password": str}`: si `limite.bloqueado` → 429 `"Demasiados intentos; espera un minuto."`; contraseña mala → `fallo` + 401; buena → 204 con `Set-Cookie` (`HttpOnly`, `SameSite=Strict`, `Max-Age=DURACION_S`, `Path=/`, y `Secure` solo si `request.url.scheme == "https"`).
    - `DELETE /sesion` → 204 y borra la cookie.
  - Lee la `API_KEY` vía `main.ajustes` en cada petición. Sin `API_KEY` → 503, como hoy.
- En `main.py`, `requiere_api_key(request: Request, clave = Security(api_key_header))`:
  1. sin `ajustes.api_key` → 503;
  2. header válido → ok;
  3. cookie válida → si el método no es `GET`/`HEAD` y falta `X-Requested-With: fetch` → 403; si no, ok;
  4. si no → 401.
